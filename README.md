# Pokémon Battle Prediction — FDS Kaggle Challenge (Gen 2 OU)

Official team repository for the **FDS Kaggle Competition** (*Fundamentals of Data Science* — Sapienza University of Rome).

## Project Overview

The goal of this competition is to build a **supervised binary classification** model capable of predicting the winner of a Pokémon battle in the competitive *Generation 2 OverUsed (OU)* format (`player_won`: `1` if Player 1 wins, `0` if Player 1 loses), observing **only the initial team composition and the first 30 active turns** of the battle.

### Competition Constraints & Guidelines
* **Evaluation Metric:** Classification Accuracy.
* **Classical ML Only:** Strictly classical Machine Learning algorithms (Logistic Regression, LightGBM, CatBoost, XGBoost, Stacking Ensemble). **Neural networks are prohibited.**
* **Allowed Data:** Strictly the provided competition files (`train.jsonl`, `test.jsonl`, and `type_chart_gen2.csv`). **No external databases, external replay datasets, Smogon usage statistics, or manually collected tables.**
* **No Pretrained Models:** All models, KO detectors, and meta-learners are trained from scratch on the competition training data.
* **Submission Format:** Strict alignment with `sample_submission.csv` (5,000 rows, IDs `0..4999`, binary predictions `{0, 1}`).

## Model Progression & Benchmark Results

The repository documents the iterative engineering progression across versions:

| Version | Architecture | Key Characteristics | CV Accuracy (15-fold) | OOF Accuracy | Output File |
| :--- | :--- | :--- | :---: | :---: | :--- |
| **Baseline (`src/`)** | LightGBM / HistGBDT | End-state HP, static lead diffs, basic timeline dynamics | ~66.80% | — | `submission_baseline.csv` |
| **V1 (`first_version/`)** | Scaled Logistic Regression ($C=0.1$) | 71 base features (HP left, fainted counts, status, boosts, team stats) | 66.88% ± 0.61% | — | `first_version/submission.csv` |
| **V2 (`second_version/`)** | Soft Voting: LightGBM + CatBoost | 470 features (Spikes, active species HP, move bags, survivor duel, P1-trained KO detector) | 68.64% ± 0.86% | — | `second_version/submission.csv` |
| **V3 (`third_version/`)** | Tri-Model Bagged Ensemble: XGB (60%) + LGB (30%) + CAT (10%) | 200 features selected from 565 Gen 2 OU domain features, Soft Roster Reconstruction, momentum derivative ($\tau=0.505$) | 68.87% ± 0.77% | **69.04%** | `third_version/submission.csv` |
| **V4 (`fourth_version/`)** | Two-Level Stacking Ensemble (L0: XGBoost / LightGBM / CatBoost; L1: L2-Logistic Regression) | Top 200 features selected from 565 Gen 2 OU domain features; automated data-driven meta-learner weights and intercept calibration | **69.11% ± 0.78%** | **69.11%** | `fourth_version/submission.csv` |

## How to Run & Reproduce

All scripts are executed from the project root:

### 1. Run Version 4 (Stacking Ensemble — Final Competition Submission)
```bash
python fourth_version/train.py
```
This command:
1. Loads the training set (10,000 battles) and test set (5,000 battles).
2. Assembles 565 candidate features covering Gen 2 OU mechanics, soft P2 team reconstruction, timeline momentum, and duel matchups.
3. Ranks and selects the top 200 most discriminative features using gradient boosting gain.
4. Trains 3 complementary Level-0 base models (XGBoost, LightGBM, CatBoost) across 15 folds (5-fold $\times$ 3 repeats).
5. Fits a Level-1 L2-Regularized Logistic Regression meta-learner on Out-Of-Fold probabilities.
6. Generates `fourth_version/submission.csv` with 5,000 binary predictions.

### 2. Run Version 3 (Tri-Model Bagged Ensemble)
```bash
python third_version/train.py
```

### 3. Run Version 2 (LightGBM + CatBoost Soft Voting)
```bash
python second_version/train.py
```

### 4. Run Version 1 (Logistic Regression Baseline)
```bash
python first_version/train.py
```

### 5. Run Initial Modular Baseline
```bash
python src/cv_splitter.py
python src/train_pipeline.py
```

## Key Feature Engineering Highlights

1. **Unrecorded P2 Knock-Out Detection (`features_lookup.py`)**:
   In the raw data, Player 2's faints are frequently omitted when a Pokémon faints at turn-end (the timeline jumps directly to the replacement). An auxiliary classifier trained on Player 1's recorded faint events identifies unrecorded Player 2 faints based on residual HP, move categories, Spikes, and self-KO moves.
2. **Soft P2 Team Reconstruction (`features_lookup.py`)**:
   Leverages the training team library and co-occurrence statistics to infer the probability distribution and expected base stats of Player 2's hidden bench Pokémon.
3. **Gen 2 OU Domain Dynamics (`features_domain.py`)**:
   * **Rest vs. Hostile Sleep**: Distinguishes full-HP self-inflicted Rest from hostile sleep moves (`spore`, `hypnosis`, `sleeppowder`).
   * **Spikes Hazards & Spinblocking**: Models Flying-type immunity to Spikes, Ghost-type spinblocking, and "Dead on Entry" hazards for low-HP grounded switch-ins.
   * **Offensive & Defensive Fuel Split**: Computes physical and special bulk/offense according to Gen 2 mechanics, including the 50% Attack reduction under burn status.
4. **Timeline Momentum & Turn 30 Initiative (`features_timeline.py`)**:
   Extracts recent damage velocity, early vs late HP derivatives, switch pressure, and turn 30 immediate KO threat.
